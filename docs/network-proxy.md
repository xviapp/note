# Android 网络代理

页间不内置代理核心，可以使用本机或局域网里已有的代理，例如 Clash、v2rayNG、sing-box 的 SOCKS5 或 HTTP 端口。设置入口在「设置 → 服务器 → 网络代理」，只对本应用生效，不修改系统代理，也不需要 VPN 权限。

## 设置

- **代理地址**：支持 `socks5://主机:端口` 和 `http://主机:端口`，只写 `主机:端口` 时按 SOCKS5 处理；`socks://`、`socks5h://` 都按 SOCKS5 保存。地址必须带端口，不支持用户名和密码，也不支持 `https://` 代理。保存后显示规范化的地址。推荐使用 SOCKS5：域名由代理解析，检测也能确认对方确实是 SOCKS5 服务。
- **使用代理**：填写地址后才能打开。关闭时一律直连。
- **连接 VPN 时直连**：代理开启后可以打开。本应用的默认网络经过 VPN 时（分应用排除页间的 VPN 不算），WebView 和原生请求都直连，也不检测代理；VPN 断开后恢复代理。
- **检测**：立即重新检测一次。

开关、地址和 VPN 选项保存在本机 `note_proxy` 偏好中。

## 检测与直连回退

代理开启后，在需要联网时才检测，不做后台定时检测：

- 检测只确认代理本身能连上，不检测它能否访问外网。SOCKS5 建立 TCP 连接后发送 SOCKS5 握手，要求不认证；HTTP 代理只确认端口能连上。连接超时 1.5 秒，读取超时 1 秒。
- 检测成功后 60 秒内、失败后 15 秒内复用上次的结果。超过这个时间，下一次请求（`api()`、上传、流式请求、随手记同步、原生下载等，都会先等待 `proxyReady()`）会先重新检测。
- 以下情况立即重新检测：打开代理、保存地址、切换 VPN 选项、点击「检测」、默认网络变化、应用回到前台，以及经代理的请求连不上网络时。
- 代理能连上时，WebView 和原生请求都走代理。本机回环地址和局域网地址（10/8、172.16/12、192.168/16、169.254/16、100.64/10、`*.local`、`*.lan` 等）始终直连。
- 代理连不上时清除 WebView 代理，改为直连，并提示「代理 … 无法连接，已改用直连」。直连期间页面右上角显示警告图标，点开可以看到原因并重新检测。之后某次检测成功时会自动切回代理，并提示「代理已恢复」。提示只在状态变化时出现一次。
- 请求因网络错误失败、而代理检测也确认已断开时，读取请求（GET）会改用直连重试一次；保存等写操作不会自动重试，界面照常提示后由用户重试。原生下载和随手记上传（带幂等键）也会直连重试一次。

注意：代理断开后流量会直接发出，这是有意的设计，不提供“断开即禁止联网”的选项。

## 实现

- `NoteProxyNetwork`：保存设置，监听默认网络和 VPN，在主线程维护状态（`off` / `vpn` / `checking` / `proxy` / `direct`）。同一时间只运行一个检测；检测期间设置发生变化时，旧结果作废并重新检测。用 AndroidX `ProxyController` 设置 WebView 代理，在页面准备完成后才首次设置，因为在 `onCreate` 中设置会让包内资源加载停顿；`proxy()` 和 `call()` 为原生 HTTP 请求选择线路。
- `ProxyAddress` 负责解析和规范化地址，`ProxyProbe` 负责检测。
- `NoteProxyPlugin`（Capacitor 插件 `NoteProxy`）提供 `prepare`、`getStatus`、`check({ force })`、`setEnabled`、`setUrl`、`setBypassOnVpn` 和 `status` 事件。地址无效时 `setUrl` 拒绝并返回错误码 `INVALID`、`SCHEME`、`AUTH` 或 `PORT`，中文提示由 `src/proxy.ts` 生成。
- `src/proxy.ts` 维护前端状态、请求前检测和切换提示；设置界面在 `src/components/ProxySettings.tsx`。

从旧版本升级后，旧的内置代理数据（`files/mmkv`、WorkManager 数据库）会在首次启动时清理一次。旧的订阅和开关不会迁移，需要重新填写代理地址。
