# Android 应用内网络代理

note 与 web 共用独立仓库 `xviapp/proxy-core`，本地位于同级 `../proxy-core/`。共享模块只提供代理实现和宿主接口；宿主各自负责 WebView / 浏览器适配，以及订阅、节点和状态 UI。

完整接口、初始化、构建依赖及错误码见[共享核心接口](proxy-core-api.md)。该文档由核心仓库同步，修改接口后在 proxy-core 根目录运行 `node scripts/sync-api-docs.mjs`，再用 `--check` 检查两个宿主副本。

这是一个轻量的 Proxy-only 模式：入口只监听 loopback，不修改系统代理，不启用 VPN/TUN/root，也不提供按应用分流。核心配置来自固定的默认模板，只保留 SOCKS 入站、一个当前订阅节点、直连和阻断出站；DNS、规则编辑、资源文件、备份恢复、搜索、单节点导入/分享、手工 JSON 和高级核心设置均不在功能范围内。

## 使用方式

- 应用内代理通过开关启停。只保留一个订阅；没有订阅时点击“添加订阅”，已有订阅时点击“更换订阅”，在弹窗中保存订阅地址、订阅更新间隔和连通性测试间隔。页面右侧提供“立即更新”，不显示订阅名称、地址或间隔；更新间隔默认 1440 分钟，最短 15 分钟，由 Android 后台任务按网络和省电约束调度。
- 手动更新通过设备网络直连订阅地址，明确绕过内置代理；定期更新使用 WorkManager，走同一条直连路径。
- 更新时自动测试订阅内全部节点；自动模式选择延迟最低的可用节点，手动模式优先使用指定位置的健康节点；没有可用节点时保留上一次成功的配置并提示失败。
- 设置页通过下拉菜单选择节点，选项仅包含“自动”和节点名称。选择节点进入手动模式，该节点健康时优先使用；选择“自动”恢复最快节点策略；更新、检测及操作过程中暂时禁用选择。运行中的核心会自动重载到新的选择。
- 连通性测试默认间隔 5 分钟，最短 1 分钟，仅在代理运行时检测当前节点，手动回退期间也检测指定节点；连续 3 次检测失败或延迟超过 2000 毫秒时，测试现有全部节点并选择最快的可用节点，没有可用节点时保留原选择。一次正常检测、关闭代理或切换节点会清零异常计数。连通性异常不触发订阅更新。宿主进程退出或设备休眠可能使检测延后。
- 节点测速结果和手动选择位置写入本机；手动指定的节点不可用时自动回退，并提示临时使用的节点，检测恢复后自动切回。下拉菜单保持显示手动指定的节点，回退提示说明实际使用的节点。没有节点时隐藏列表，不提供手动测试入口。

节点和订阅仅保存在各宿主自己的应用私有 MMKV 中，note 与 web 的数据互不混用。订阅更新失败时保留上一次成功的节点列表，不清空当前配置。共享模块不暴露 Activity 或 Compose UI。

## 宿主边界

- note 通过 `EmbeddedProxyController.get(context, Routing)` 提供 WebView 路由适配。单个 `observe` 监听立即获得完整状态快照，返回的 `Observation` 在插件销毁时关闭。
- Capacitor 只发送一条 `status` 事件，包含代理状态、错误码、重试时间和订阅快照；React 的订阅 hook 从同一状态派生，不单独查询或监听订阅。
- 保存 URL、手动更新和选择节点、恢复自动选择及切换下一个节点均在对应命令完成回调后结束等待；这不保证 daemon 异步重载已完成，网络可用性以 `phase == RUNNING` 为准。订阅失败由 `subscription.error` 错误码表达，中文提示由 note 生成；未知错误码也不直接显示原始内容。

- WebView 与原生下载使用同一个 loopback 入口；代理核心流量不会再次进入自身入口。
- 核心启动、网络切换或守护进程异常时，宿主清除自己的应用内代理并按宿主策略重连；应用不会替其他应用接管流量。
- 核心运行使用共享 `:daemon` 进程；订阅更新和节点测试由 WorkManager / 应用内任务完成，不再创建独立的订阅服务或订阅通知。
- 运行配置不会读取旧版本的系统模式、路由、DNS、监听认证、代理共享等设置；旧节点列表只在首次启动时做一次兼容迁移，之后由订阅完全覆盖。

## 来源与构建

代理代码来自 v2rayNG / AndroidLibXrayLite / Xray-core 的固定版本，修改后作为 `proxy-core` library 同时供两个宿主构建。共享模块保留 GPL-3.0 许可证。

首次获取 note 后，从 note 根目录执行 `git clone https://github.com/xviapp/proxy-core.git ../proxy-core`；已有共享目录则直接使用，不重复克隆。核心也提供独立 Gradle wrapper；宿主只声明模块依赖，Xray Java/JNI 由核心自动下载、校验并打包，不提交生成产物。

note 使用自己的 `NoteApplication`，在每个进程调用 `ProxyCore.initialize(this, true)`；共享模块不接管宿主 Application，不替换已有 WorkManager 配置。来源和原生版本统一通过 `ProxyCore.info()` 获取。

```bash
# note
cd note/android
./gradlew :v2ray:testDebugUnitTest :app:testDebugUnitTest --no-daemon

# web
cd ../../web
./gradlew :v2ray:testDebugUnitTest :app:testDebugUnitTest --no-daemon
```

设备测试只使用本机测试服务，不会读取真实订阅；真实订阅和公网节点需要在隔离测试安装中自行验证。
