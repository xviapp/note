# 项目与文件引用

选择「新建 → 更多类型 → 项目」，应用创建项目目录，以及其中的 `todo`、`issue`、`note` 三个子目录。项目页自动汇总这些目录及更深子目录中的 Markdown 文件，分类标签分别使用待办清单、问题提示和笔记图标。其他格式的文件仍可保存在目录中，但不进入项目列表。

项目页标题下方不提供通用的「新建」，在各分类中用「新建待办」「新建问题」「新建笔记」添加条目，填写标题和可选说明；每一条都会保存为所属目录中的独立 Markdown 笔记。点击条目后，正文阅读区底部固定显示居中且限制宽度的快捷输入：问题用于「补充讨论」，待办用于「记录进展」，笔记用于「追加笔记」。未使用时只显示一行输入框，获得焦点或开始输入后再展开标题框；宽屏上标题和正文输入框等宽，正文输入框可拖动调高，展开目录后仍与正文居中对齐；标题可选，内容可以只写文字、只添加照片或两者都有。点击正文输入框右下角的照片按钮可一次选择多张 PNG、JPEG、GIF、WebP 或 AVIF 图片，上传后显示缩略图，可在提交前移除；照片会作为正文图片和附件写回原 Markdown。问题和待办的记录写入正文中的「## 讨论」或「## 进展」小节（没有时自动在末尾创建，小节后还有其他二级标题时插在小节末尾），每条以「### 2026-10-07 14:05 · 标题」开头，不写标题时只有时间；笔记的追加不带时间，标题作为二级标题，与正文连成一篇。阅读时，问题的讨论显示为一张张卡片，待办的进展显示为时间线，状态变化显示为一行小字，记录不进入「本篇目录」；在任意编辑器里打开仍是普通 Markdown。早先以「> 2026-10-07 14:05:00 +08:00」标记时间的记录照常识别，不做迁移。待办改为「已完成」、问题改为「已关闭」时可填写完成结果或结论（可留空），与状态变化记在同一条里并突出显示。回车换行，Ctrl/Cmd+Enter 保存。提交按钮在输入区获得焦点或已有输入时显示：宽屏放在正文输入框右侧，手机上与标题框同行；青藜悬浮入口位于追加区上方。输入、已上传照片和加密文件的草稿会保留在本设备并加密保存；联网后才能上传照片或提交。失败保留输入和照片，版本冲突时显式重试会接在最新正文后，保留原内容和附件。

条目页不再提供新建子笔记的入口，项目概览仍可创建新条目。顶部保留阅读设置、收藏和目录，全文编辑、历史版本、翻译、批注和已有下级笔记放在「⋯」菜单；青藜使用与其他文件一致的悬浮入口。

待办和问题的状态可在标题右侧或项目概览直接切换，显示为带颜色的状态标签，左侧图标同时表示状态（空心圆为待办，圆点为进行中，对勾为已完成或已关闭，叹号为待处理，问号为未设置或待调整）。状态变化更新文首资料，同时在「## 讨论」或「## 进展」小节记录时间和变化（如「### 2026-10-08 20:00 · 进行中 → 已完成」）；在标题右侧改为已完成或已关闭时可附上结论，项目概览中切换不询问结论；并生成历史版本；相同状态不会重复追加变更记录。已完成或已关闭后仍可追加内容，也可重新切换状态；追加内容不会自动改变状态。状态以服务器上的最新正文为准，刚追加完立即切换也不会冲突。

## 标题与状态

文件使用文首资料记录标题和状态，例如：

```markdown
---
title: '支持文件夹引用'
status: todo
---

这里写具体说明、实施方案和检查清单。
```

`title` 和 `status` 使用单行文字，可以加英文单引号或双引号。其他文首字段会原样保留。阅读时隐藏这些资料，编辑源码时可以查看和修改。

| 目录    | 状态                      | 显示文字               |
| ------- | ------------------------- | ---------------------- |
| `todo`  | `todo` / `doing` / `done` | 待办 / 进行中 / 已完成 |
| `issue` | `open` / `closed`         | 待处理 / 已关闭        |
| `note`  | 不要求状态                | 笔记                   |

缺少有效 `title` 时，项目页取正文中第一个一级标题，再回退到文件名称；代码块中的标题不参与提取。缺少状态显示「未设置」，不支持的状态显示「待调整」并保留原文。状态重复、使用多行资料或文首分隔线不完整时，需要先编辑原文件，再从项目页修改状态。

分类由项目下第一层目录名称决定，忽略大小写和名称两侧的空格。把文件或包含它的子目录在 `todo`、`issue`、`note` 之间移动后，分类随之更新，正文中的状态保留。例如，已完成的待办移入 `issue` 后，需要选择该分类支持的状态。移出这三个目录或进入回收站后，不再出现在项目列表；恢复后自动重新收录。

项目页顶部汇总待办完成进度和未关闭问题数（没有时不显示）。控制栏左侧是筛选，右侧是「打开目录」和新建按钮。列表按状态排序：进行中在前，其次待办、待处理和状态不明的条目，已完成和已关闭放在最后并加删除线。可筛选未完成待办或未关闭问题；手机上「打开目录」只显示图标。「⋯」菜单中的「刷新项目」重新读取汇总。标题和状态以已保存的正文为准，未保存的编辑草稿不参与汇总。新建和保存文件会同步更新摘要；旧文件或恢复的备份首次打开时，项目页会分批读取并自动完成整理。项目概览需要联网。

## 文件与文件夹引用

选择「新建 → 更多类型 → 文件／文件夹引用」，选取原内容并填写可选名称。引用是笔记树中的独立入口，打开后可以进入原文件或原目录；内容保留在原位置，不会复制。引用本身可以重命名、移动、收藏或删除。向引用添加内容时，需要先打开原目录。

把文件引用放在三个分类目录中，该 Markdown 原文件就会进入对应项目列表；文件夹引用会收录目标目录中的全部 Markdown 文件及下级引用。也可以将项目下第一层的文件夹引用命名为 `todo`、`issue` 或 `note`，作为该分类的索引入口。同一分类中，同一个原文件只出现一次；循环引用不会造成重复或无限遍历。

从项目概览进入引用条目时，使用该项目对应的分类页面，地址保留项目和分类信息，刷新或返回后仍保持该视图；独立打开原文件时按原位置显示。从项目页面追加内容或修改状态都会写回原文件，其他引用该文件的项目刷新后也会看到新内容和状态。删除引用保留原内容；原内容在回收站中或已永久删除时，项目页提示引用不可用。整库备份包含项目和引用关系，恢复时会映射到新文件，重新生成项目摘要。
