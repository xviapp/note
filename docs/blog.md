# 博客

把笔记库里的一个文件夹作为公开博客，绑定到单独的域名。文章默认不公开，只有手动发布后才对外可见。

## 使用

1. 在 **设置 → 博客** 选择博客目录，填写名称和简介。选好目录不会公开任何内容。
2. 在 **页面** 里为“文章”选择博客目录下第一层的一个文件夹，需要的话再为“项目”选另一个（见下文“栏目”）。
3. 在文章文件夹里打开一篇 Markdown 笔记，从 ⋯ 菜单选择 **发布到博客**，确认链接后发布。
4. 之后的修改只保存在笔记里。需要上线时，从同一菜单选择 **更新博客文章**。

设置页列出所有已发布的文章和它们的状态。“博客地址”只用于从应用里打开文章。

## 摘要

摘要显示在文章列表、搜索结果和 RSS 里。发布或更新文章时，如果正文有变化，青藜会根据要发布的版本生成一次摘要。

- 只有发布和更新时才调用 DeepSeek，保存笔记不会。正文文字没变时（比如只改了附件）沿用原来的摘要，太短的文章和“页面”直接用正文开头。
- 摘要只根据访客能看到的内容生成：HTML 注释和原始 HTML 不会显示在博客上，也不会发给青藜或出现在摘要里。
- 没有配置 DeepSeek、密钥失效、余额不足或超时时，发布照常完成，摘要取正文开头。
- 发布后可以在同一个对话框修改摘要或重新生成。改了摘要没保存就点 **更新到当前版本**，摘要会一起保存。手动改过的摘要在之后更新文章时会保留，点 **重新生成** 或清空保存后才恢复自动。
- 摘要最多 160 个字符，超出的部分截掉并加“…”。

## 主题

在 **设置 → 博客** 选择主题，保存后立刻生效。

| 主题 | 外观 |
| --- | --- |
| 页间 | 单栏，配色与应用一致，跟随系统深浅色 |
| 打字机、素白、粉紫、晴空 | 侧栏加卡片，浅色 |
| 终端 | 侧栏加卡片，深色 |

后五个主题参照 [Typing Jekyll Template](https://github.com/williamcanin/typing-jekyll-template)（MIT）。侧栏的圆形标记显示博客名称的第一个字。

## 栏目

**设置 → 博客 → 页面** 设置博客的五个栏目，设置了的栏目出现在导航里：

| 栏目 | 选择 | 地址 |
| --- | --- | --- |
| 文章 | 博客目录下第一层的文件夹 | `/blog` |
| 项目 | 博客目录下第一层的另一个文件夹 | `/projects` |
| 简历、联系、关于 | 博客目录下的一篇 Markdown 笔记 | `/resume`、`/contact`、`/about` |

**首页** 从已设置的栏目中选一个，显示在 `/`，它原来的地址跳转到 `/`。默认是文章；选中的栏目没有内容时，首页显示第一个有内容的栏目。

- **文章** 列出文章文件夹里（含子文件夹）已发布的笔记。文章文件夹里的第一层子文件夹是分类。只有文章进 RSS。
- **项目** 列出项目文件夹里已发布的笔记，样式和文章列表相同，但不进文章列表、分类和 RSS。项目文件夹里还没有已发布的笔记时，导航里不显示项目。
- **简历、联系、关于** 显示选中的笔记。没有发布过的笔记，保存时确认后会公开当前版本；已发布的笔记保持已发布的版本。页面不进文章列表、分类和 RSS，原来的 `/posts/…` 链接会跳转到页面地址。
- **已发布、但不在文章或项目文件夹里、也没有选作页面的笔记不会显示**，设置页把它标为“未显示”。移进其中一个文件夹或选作页面后再次显示，不需要重新发布。
- 文件夹移出博客目录、移入回收站或被加密后，对应栏目不再显示，设置保留，移回后恢复。更换博客目录会清空文章和项目的选择。
- 打印页面时不含侧栏和导航，简历可以直接打印成 PDF。

## 公开的内容

- 发布时的标题、摘要和正文，以及**正文引用**的图片和附件。笔记的其他附件、批注、青藜对话和历史版本都不公开。
- 正文里指向其他笔记的链接：目标已发布时指向对应文章，否则只保留文字。
- 文章文件夹里第一层子文件夹的名称，作为文章分类。

站点提供设置了的栏目、分类页、文章页、RSS（`/feed.xml`）和站点地图（`/sitemap.xml`）。公式在服务端渲染；只有含 Mermaid 图表的文章才加载博客自己的脚本。内容安全策略放行 Cloudflare Web Analytics，域名开启自动注入时可以统计访问。

## 下线

以下情况文章会立刻从博客上消失：

| 操作 | 再次显示 |
| --- | --- |
| 取消发布 | 重新发布 |
| 移出文章或项目文件夹（且没有选作页面）、移入回收站 | 移回文件夹或从回收站恢复 |
| 关闭博客或更换目录 | 重新选择包含它的目录 |
| 笔记或上级目录被加密 | 解除加密后重新发布（发布记录已删除） |
| 博客目录本身移入回收站 | 恢复后重新选择目录 |

加密的笔记和文件夹不能发布，也不能作为博客目录。加密文件夹内即使有设为“不加密”的笔记，也不会显示。

搜索引擎和 RSS 阅读器可能已经保存了下线前的内容，这部分无法由博客收回。

## 备份

备份包含笔记和已发布的版本，但不包含发布状态和博客设置（含主题和栏目）。恢复出的副本不会自动公开，需要的话重新选择目录并发布。

## 部署

博客是单独的 Worker，与应用共用 D1 和 R2。它不修改笔记，没有登录和 `/api` 接口，所以博客域名上访问不到私有内容。

博客显示的内容（设置、在线文章和可访问的文件）保存为 R2 中的一份快照 `blog/snapshot.json`。访客和爬虫只读这份快照，不查询 D1。应用在每次可能影响博客的修改之后、返回结果之前重建快照，内容没变时不重写；请求中途出错时也会重建，因为可能已经写入了一部分。保存正文、新建笔记、阅读进度、批注、青藜对话、翻译、读书、日记、项目、随手记、上传、导入和备份恢复都不会影响博客，不触发重建。重新加密的文件如果被公开文章引用，也会重建。R2 每秒只接受一次对同一对象的写入，连续修改时应用会稍等后用最新数据重写；仍然失败时记录日志，由下一次修改或定时任务（每 30 分钟）补上。

快照不存在时（比如第一次部署），博客会从 D1 生成一份，所以博客 Worker 仍需要 D1 绑定。直接用 `wrangler d1 execute` 修改数据库不会更新快照，需要紧急下线时，改完后删除 R2 中的 `blog/snapshot.json`，或在应用里做任意一次会影响博客的修改。

1. 把域名加入管理应用的同一个 Cloudflare 账号。
2. 复制配置，并按 `wrangler.selfhost.jsonc` 填写账号、D1 和 R2，在 `routes` 写上域名：

   ```bash
   cp wrangler.blog.example.jsonc wrangler.blog.selfhost.jsonc
   ```

3. 部署。命令会先构建并迁移 D1：

   ```bash
   npm run deploy:blog
   ```

本地开发用 `npm run dev:blog`，地址是 `http://localhost:8788`。部署应用不会更新博客，反之亦然；两者共用数据库，改动迁移后都要部署。先部署应用（`pnpm run deploy`）再部署博客：只有应用会更新快照，只部署新博客时，博客会停在它自己生成的第一份快照上，之后的发布、下线和加密都不会生效。
