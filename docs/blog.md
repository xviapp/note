# 博客

把笔记库里的一个文件夹作为公开博客，绑定到单独的域名。文章默认不公开，只有手动发布后才对外可见。

## 使用

1. 在 **设置 → 博客** 选择博客目录，填写名称和简介。选好目录不会公开任何内容。
2. 在目录内打开一篇 Markdown 笔记，从 ⋯ 菜单选择 **发布到博客**，确认链接后发布。
3. 之后的修改只保存在笔记里。需要上线时，从同一菜单选择 **更新博客文章**。

设置页列出所有已发布的文章和它们的状态。“博客地址”只用于从应用里打开文章。

## 公开的内容

- 发布时的标题、摘要和正文，以及**正文引用**的图片和附件。笔记的其他附件、批注、青藜对话和历史版本都不公开。
- 正文里指向其他笔记的链接：目标已发布时指向对应文章，否则只保留文字。
- 博客目录下第一层文件夹的名称，作为文章分类。

站点提供首页、分类页、文章页、RSS（`/feed.xml`）和站点地图（`/sitemap.xml`）。公式在服务端渲染；只有含 Mermaid 图表的文章才加载脚本。

## 下线

以下情况文章会立刻从博客上消失：

| 操作 | 再次显示 |
| --- | --- |
| 取消发布 | 重新发布 |
| 移出博客目录、移入回收站 | 移回目录或从回收站恢复 |
| 关闭博客或更换目录 | 重新选择包含它的目录 |
| 笔记或上级目录被加密 | 解除加密后重新发布（发布记录已删除） |
| 博客目录本身移入回收站 | 恢复后重新选择目录 |

加密的笔记和文件夹不能发布，也不能作为博客目录。加密文件夹内即使有设为“不加密”的笔记，也不会显示。

搜索引擎和 RSS 阅读器可能已经保存了下线前的内容，这部分无法由博客收回。

## 备份

备份包含笔记和已发布的版本，但不包含发布状态和博客设置。恢复出的副本不会自动公开，需要的话重新选择目录并发布。

## 部署

博客是单独的 Worker，与应用共用 D1 和 R2。它只有读取功能，没有登录和 `/api` 接口，所以博客域名上访问不到私有内容。

1. 把域名加入管理应用的同一个 Cloudflare 账号。
2. 复制配置，并按 `wrangler.selfhost.jsonc` 填写账号、D1 和 R2，在 `routes` 写上域名：

   ```bash
   cp wrangler.blog.example.jsonc wrangler.blog.selfhost.jsonc
   ```

3. 部署。命令会先构建并迁移 D1：

   ```bash
   npm run deploy:blog
   ```

本地开发用 `npm run dev:blog`，地址是 `http://localhost:8788`。部署应用不会更新博客，反之亦然；两者共用数据库，改动迁移后都要部署。
